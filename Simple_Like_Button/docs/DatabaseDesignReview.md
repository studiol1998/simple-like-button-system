# データベース設計の確認メモ

このメモは、にくきぅSYSTEMs（Nikukiu-SYSTEMs）が、プロジェクト直下にある現行仕様書と設計草案を最初の実装に向けて整理した検討記録である。仕様書に代わるものではなく、未決の動作や設計を確定するものでもない。

設計上の決定事項は [DatabaseDesignDecisionLog.md](DatabaseDesignDecisionLog.md) に記録する。このメモの初期検討事項・推奨案と内容が異なる場合は、決定ログを優先する。

実装作業の段階と残件は [ImplementationPlan.md](ImplementationPlan.md) に整理している。

本書では、いいねの集計対象を区別する値を「identifier（識別子）」と表記する。\
管理画面などで使用する「Like ID」も同じ値を指す。

## 基本データ方針

- いいねはまず個別イベントとして記録し、集計処理後は個別イベントを削除して、累計値・期間別集計値を保存する。
- ページタイトル、リファラー、生のIPアドレス、生のブラウザ識別値、User-Agentは収集・保存しない。
  設置先URLは `data-url`、canonical、`og:url`、現在URLの順に取得し、query・fragmentを除いてLike成立後だけ保存する。
- `identifier`（識別子） はLikeの集計対象を識別する値として扱う。
  UTF-8（`utf8mb4`）、最大100 Unicode コードポイントとし、Unicode文字・数字・句読点・記号、およびASCIIの `-` `_` を許可する。空白、制御文字、それ以外のASCII記号は受け付けない。
- 未集計イベントにはUTCの送信時刻など、集計に必要な情報を保持する。
  押下制限や不正アクセス調査に必要な情報は、個別イベントとは分離して管理し、それぞれの用途に必要な期間に限って保持する。
  当初設計では、調査用 ip_hash を設置ごとの秘密鍵によるHMAC-SHA-256で生成し、最長60日で削除する方針とした。ただし、β-2ではIP関連情報の保存先と用途が分離されているため、保存対象・保持期限・削除契機は現行実装との照合を要する。
- レート制限はidentifier（識別子）ごと・匿名ブラウザごとに適用し、直近24時間の回数を1～5回（初期値3回）で制限する。
  期限切れの専用記録は次の押下時に削除する。
- 集計処理は選択された開始しきい値（初期値1,000件）到達時または管理画面アクセス時に起動する。
  大きな未処理分を一度に同期処理しない。
- 日別集計は最大5年かつ最大50,000行とし、いずれかを超える場合は古い日別データを月別にまとめる。
  日別集計データの行数上限は、β-2では50,000行の固定値とする。v1.0.0でも同じ仕様を維持する方針とし、v1.0.1以降、管理画面から上限値を変更できる機能の追加を検討する。変更可能な範囲や設定変更時の既存データの扱いについては、実装を決定する段階で検討する。
- 時間帯別集計はβ版から実装する。サイト全体のいいねを現在のタイムゾーンで1時間単位に分けて月別集計し、直近24か月分を保持する。
  公開版へ含めるかは自サイトでの試用後に判断する。
- タイムゾーン変更時は、未集計分も含めたそれまでの累計値・期間別集計値・時間帯別集計値を確定して `log/` に退避し、稼働中データをリセットして新しいタイムゾーンで集計を開始する。
  変更前に確認ダイアログを表示する。［はい］の後は「現在のデータを集計中」「集計したデータを格納」の進行状況を表示し、完了後は集計・格納の完了と保存先 `log/` を通知する。
  公開件数も0から再開する。
- DBの時刻はUTCで扱う。サイト上の件数表示は初期状態でオフとし、管理画面から切り替えられるようにする。
- 動作状態は有効・メンテナンスの2種類とする。

## 現行資料から読み取れる候補項目

### 個別イベントと集計データ

| データ | 方針 | 実装時に定めること |
| --- | --- | --- |
| 未集計いいねイベント | 集計前のイベントを保持し、集計成功後に削除する | SQL型、索引、削除のトランザクション方法 |
| 累計値 | identifier（識別子）ごとの総数を現在のタイムゾーン期間中保持し、変更時にログへ退避してリセットする | 再集計・訂正の扱い |
| 期間別集計 | 日別を5年・50,000行まで保持し、月別で5年保持後に年別化する。年別は保持する。タイムゾーン変更時はログへ退避してリセットする | バッチは最大500件。更新と元イベント削除は同一トランザクション |
| 設置先URL | `identifier`（識別子）、正規化URLのSHA-256、URL、初回・最終確認時刻を保持する。同じIDに複数URLを許可する | URL候補の優先順位に従い、query・fragmentを除去してLike成立後だけ登録する |
| 不正アクセス調査用 `ip_hash` | 当初設計では60日間保持し、期間を超えた記録を削除する方針とした。β-2の保存対象・保持期限・削除契機は現行実装との照合を要する。保持期間の選択機能はv1.0.1以降に追加する。 | IPを取得できない場合の扱い |

### `settings` テーブル

設定にはメンテナンス状態、レート制限の時間・回数、公開件数表示の有効・無効、自動集計開始件数を含める。自動集計開始件数はドロップダウンで1,000件（初期値）、2,000件、4,000件、6,000件、8,000件、10,000件から選択する。
日別集計行数上限は、β-2では50,000行の固定値とし、v1.0.0でも同じ仕様を維持する方針とする。v1.0.1以降、管理画面から変更できる機能の追加を検討する。なお、自動集計開始件数と日別集計行数上限は、それぞれ独立した設定項目として扱う。

## 残っている確認項目

集計失敗時のロールバック・再試行と同時実行防止は、2026-09-29にXAMPPのMariaDB上で一時DBを使って確認済みである。詳細は [DatabaseDesignDecisionLog.md](DatabaseDesignDecisionLog.md) を参照すること。

CSV数式対策は、合成テストIDを含むアーカイブをMicrosoft Excelで開き、identifier（識別子）が文字列として表示され数式が実行されないことを2026-09-29に確認済み。

- Apache以外のWebサーバーでは、config/ および log/ への外部からの直接アクセスを拒否する設定を整える。

確定済み方針と更新履歴は [DatabaseDesignDecisionLog.md](DatabaseDesignDecisionLog.md) を参照する。旧ベータ版の挙動を現行仕様として採用しない。
