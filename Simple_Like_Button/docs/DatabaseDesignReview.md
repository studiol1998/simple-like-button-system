# データベース設計の確認メモ

このメモは、プロジェクト直下にある現行仕様書と設計草案を、最初の実装に向けて整理したものです。仕様書に代わるものではなく、未決の動作や設計を確定するものでもありません。

みやびさんと個別に確認した決定事項は [DatabaseDesignDecisionLog.md](DatabaseDesignDecisionLog.md) に記録します。このメモ末尾にある初期の質問・推奨案と内容が異なる場合は、決定ログを優先してください。

実装作業の段階と残件は [ImplementationPlan.md](ImplementationPlan.md) に整理しています。

## 基本データ方針

- いいねはまず個別イベントとして記録し、集計処理後は個別イベントを削除して、累計値・期間別集計値を保存する。
- ページタイトル、URL、リファラー、生のIPアドレス、生のブラウザ識別値、User-Agentは保存しない。
- `identifier` は意味を解釈しない識別子として扱う。UTF-8（`utf8mb4`）、最大50文字とし、前後の空白を除去してから検証する。空文字、改行、NULL文字は受け付けない。
- 未集計イベントにはUTCの送信時刻、レート制限用 `client_hash`、不正状況調査用 `ip_hash` を保持する。個別イベントを集計後に残す期間は各用途に必要な期間に限る。
- `ip_hash` は設置ごとの秘密鍵を使ったHMAC-SHA-256で作成し、最長60日で削除する。秘密鍵はデータベースではなく設定ファイルに保存する。
- レート制限はLike ID（作品）ごと・匿名ブラウザごとに適用し、直近24時間の回数を1〜5回（初期値3回）で制限する。期限切れの専用記録は次の押下時に削除する。
- 集計処理は選択された開始しきい値（初期値1,000件）到達時または管理画面アクセス時に起動する。大きな未処理分を一度に同期処理しない。
- 日別集計は最大5年かつ最大50,000行とし、いずれかを超える場合は古い日別データを月別にまとめる。50,000行はプログラム設定で変更可能にする。
- 時間帯別集計はβ版から実装する。サイト全体のいいねを現在のタイムゾーンで1時間単位に分けて月別集計し、直近24か月分を保持する。公開版へ含めるかは自サイトでの試用後に判断する。
- タイムゾーン変更時は、未集計分も含めたそれまでの累計値・期間別集計値・時間帯別集計値を確定して `log/` に退避し、稼働中データをリセットして新しいタイムゾーンで集計を開始する。変更前に確認ダイアログを表示する。［はい］の後は「現在のデータを集計中」「集計したデータを格納」の進行状況を表示し、完了後は集計・格納の完了と保存先 `log/` を通知する。公開件数も0から再開する。
- DBの時刻はUTCで扱う。サイト上の件数表示は初期状態でオフとし、管理画面から切り替えられるようにする。
- 動作状態は有効・メンテナンスの2種類とする。

## 現行資料から読み取れる候補項目

### 個別イベントと集計データ

| データ | 方針 | 実装時に定めること |
| --- | --- | --- |
| 未集計いいねイベント | 集計前のイベントを保持し、集計成功後に削除する | SQL型、索引、削除のトランザクション方法 |
| 累計値 | 識別子ごとの総数を現在のタイムゾーン期間中保持し、変更時にログへ退避してリセットする | 再集計・訂正の扱い |
| 期間別集計 | 日別を5年・50,000行まで保持し、月別で5年保持後に年別化する。年別は保持する。タイムゾーン変更時はログへ退避してリセットする | バッチは最大500件。更新と元イベント削除は同一トランザクション |
| 調査用 `ip_hash` | HMAC値のみを保存し、最長60日で削除する | IPを取得できない場合の扱い |

### `settings` テーブル

設定にはメンテナンス状態、レート制限の時間・回数、公開件数表示の有効・無効、自動集計開始件数を含めます。自動集計開始件数はドロップダウンで1,000件（初期値）、2,000件、4,000件、6,000件、8,000件、10,000件から選択します。日別集計行数上限は初期値50,000件で、プログラム設定から変更可能にします。この二つの件数上限は別の設定です。
