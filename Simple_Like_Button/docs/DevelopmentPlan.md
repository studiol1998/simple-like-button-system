- エラー解除後の再実行では2件だけを反映し、続けて実行した集計は0件となり、二重加算がないことを確認。
  さらにPHPプロセス2つを同時に動かし、一方が2件を処理、もう一方が0件を処理し、最終累計2件・未集計0件となることを確認した。

古いデータの圧縮とタイムゾーン変更の中断・再開は、2026-09-29にXAMPP MariaDBの一時DBと隔離したファイル領域で確認済み。
5年境界による日別→月別、月別→年別の移行、既存集計への加算、日別50,000行上限（50,001行から1行を月別へ移行）で件数が保持されることを確認した。
タイムゾーン変更では、500件処理後の再開、アーカイブ保護エラー時に旧タイムゾーン・集計511件・メンテナンス状態を維持すること、エラー解消後の再開とコミット後復旧を確認。

過去の「50,001行から1行を月別へ移行」は、旧ImplementationPlan日英の結果記録である。対象となった識別子数、各識別子の日付分布、元データ作成方法、呼び出した処理・バッチ条件を再現できる試験コードは確認できず、これらの条件は未確認とする。

50,001件目のLikeや50,001行目の生成が自動処理を直接起動したこと、全識別子・全時点で上限が厳密に守られることまで検証済みとはしない。

別の現行tests/aggregation-review-tests.phpでは、SQLiteメモリDBとMySQL用SQLの試験アダプターを使い、2か月前の月初日という同じ日付にtarget-00000以降の50,002個の異なる識別子を各1件のday行として直接INSERTする。UTC・バッチ2件でaggregateBatchを呼び、month行が2件できること、Dashboard月別合計が前後で保たれること、再実行して二重加算しないことを検査する。

この現行コードの条件は、過去の50,001行のMariaDB試験と同一ではない。今回は実行せず、実MySQLのロック・並行処理や設計上の適用範囲の確定根拠にはしない。第4章とSpecification第5.3節の未確認事項は維持する。

以下のCSV数式対策は同日の試験記録である。

- テスト用のidentifier（識別子） `=1+1`、`+SUM(1,1)`、`-1+1`、`@SUM(1,1)` などを含むアーカイブCSVを一時DBから生成し、Microsoft Excelで開いた。
- `lifetime_totals.csv` のA列と `period_aggregates.csv` のC列で、先頭アポストロフィ付きの文字列として表示され、数式は評価されなかった。
- 確認用アーカイブはXAMPPの `log/csv-safety-test-20260929/` に置き、テスト専用と明記した。

これらは合成テストデータであり、通常入力を許可する例ではない。現行のpollyanna_identifier_is_validはASCIIの「-」「_」以外の記号を拒否するため、上記の「=」「+」「@」や括弧等を含む値は通常の識別子入力規則に適合しない。CSVの数式対策は出力側の保護として維持する。

2026-09-29の旧日英決定ログから確認できるのは、一時DBからアーカイブを生成してExcelで確認したことまでである。この4種類の値が通常の公開APIから登録されたのか、テスト専用経路・直接SQL等で投入されたのかを示す記録は、確認したリポジトリ内の資料・試験コードから見つからず、当該試験の投入経路は未確認とする。

別の現行試験tests/runtime-compatibility-tests.phpでは、SQLiteメモリDBの累計テーブルへ「=SUM(1,2)」「+formula」「-formula」「@formula」等を直接INSERTし、ReflectionMethodで実CSVライターを呼ぶテスト専用経路を確認できる。

これは公開APIの入力受理を試験するものでも、2026-09-29のExcel試験と同じ投入経路だったことを証明するものでもない。本修正ではこの試験を実行していない。

### 3.3 管理セキュリティ試験の範囲と限界

以下の相対コマンドの実行基準は、リポジトリ直下ではなくSimple_Like_Button/（D:\Kaihatu\イイネボタン\Pollyanna\Simple_Like_Button）である。評価対象のPHP CLI実行ファイルを指定する。ここに示すコマンドは実行案内であり、本調査では実行していない。

回帰ランナーはCLI・proc_open、各スイートに必要なsession・PDO・pdo_sqlite等を必要とする。拡張不足はSKIPでありPASSではない。

終了値は0が全通過、1が失敗、2が未完了。子プロセスはPHP_BINARYと親のphp.ini（未読込時は-n）を使用する。

追加INI走査は環境に依存し、呼出し時の個別-d指定は自動継承しない。必要な拡張は実際に選択した設定で有効にする。

回帰8スイートは許可リスト方式で、実MySQL・HTTP試験を自動実行しない。

HTTP試験は別途CLI・proc_open・pdo_sqlite・sessionとループバック通信が使用できる隔離環境で実行する。並行試験もCLIプロセス起動と書込可能な専用一時セッション領域が必要である。

本番資格情報や実設定で実行せず、OS一時領域への作成・削除が伴うことを確認する。詳細は既存tests/README.mdと各試験コードを参照する。

以下はAdminSecurityMigrationに記録された試験方法・限界であり、本工程での実行結果ではない。SQLを代替した新規設置の自動試験と、専用DBによる通し試験は区別する。

```text
php tests/run-regression.php
php tests/admin-security-http-tests.php
php tests/admin-session-concurrency-tests.php
```

run-regression.phpは通信なしの単体・回帰試験、admin-security-http-tests.phpは明示実行するローカルHTTP統合試験である。並行セッション試験は後述する。

HTTP試験は一意なOS一時ディレクトリにコードとダミー設定を複製し、127.0.0.1だけで
2つのサーバーを起動し、同じSIDの管理GET・設定POSTも同時に送信する。
永続DBには接続せず、実際のTLSは使わず信頼済み終端ヘッダーを
模擬する。終了時にサーバーと一時ディレクトリを片付ける。

本物のTLS・レンタルサーバー・MySQL全機能・ブラウザーのCookie送信判断を検証した
ものではない。旧HTTPテストにはPHPSESSIDやHTTP運用を前提にしたものがあり、
今後、隔離環境向けの対応が必要である。これらを本番で実行しない。

並行試験は自分で作成したOS一時ディレクトリのPHPファイルセッションだけを使用し、
2〜3つのPHP CLIプロセスを起動する。7シナリオでGET相当・実設定保存関数、
ログアウト、期限境界、CSRF更新、別SIDでのパスワード変更の順序を確認し、
不要な503/RETRYは一件でも失敗にする。保存方式依存の読み取り・書き込み・closeの
失敗通知は注入したハンドラーで、破損はネイティブの一時セッションファイルでも試験する。
OSのディスク故障や電源断を再現した試験ではない。

### 6.2. 日別データ保持・集約仕様の再評価（②調査・検証）

正式公開後の保守・改善フェーズで、まず既存仕様と実装を洗い出して再検証する。

確認対象は次のとおり。

- 現行50,000行上限の適用範囲。全体・識別子単位などの扱いを実DBでも確認する。
- 5年間の保持条件と件数上限の関係。日別詳細が実際に何年残るかを評価する。
- 日別から月別への集約条件と境界、月別から年別への起算点。
- 集約処理の実行タイミング、分割回数、ロック・トランザクションと処理負荷。
- 100,000行以上への上限変更の妥当性。
- 日別保持期間を選択可能にする必要性。
- 保持期間短縮により日別から月別などへ粒度が不可逆的に変わることへの対応。説明・確認・バックアップ等の必要性を検討する。

上限引き上げ、保持期間選択、確認UI等は実装決定事項ではない。
Specificationに記録した原設計判断を保持しつつ、実測と検証に基づいて判断することとする。

### 6.3. 暫定的な負荷モデル（②の検証条件）

自サイトの現在の設置想定を300識別子以上、1年後を400識別子以上とする。
日次押下識別子率を40～60％と仮定し、400識別子なら1日に160～240識別子で少なくとも1回の押下が起きるモデルを用いる。

40～60％は実測値ではなく、サイト運営経験に基づく暫定的な設計仮定である。
日々の変動が大きくなり得るため、週・月単位で平均的な負荷を捉える値として扱う。これは押下総数や毎日一定の新規行数を保証する値ではない。

日別レコードが識別子×日付につき1行生成されるか、件数上限がシステム全体かについては、第4章の静的観測を検証仮説とし、実装経路と実DBで確認する。
未確認条件から保持年数を確定計算しない。

### 6.4. 検証環境（②の検証条件）

高性能な共用サーバー環境と、標準的な共用サーバー環境の双方を想定し、データ保持・集約処理の動作および負荷を検証する。

特定事業者・プランを必須条件にはしない。
識別子数、日次の活動分布、データ量、集約処理、管理アクセス頻度などの試験条件を記録し、環境差と結果の適用範囲を明示する。
