# 管理画面の設計案

作成日：2026-10-03。3タブ構成と設定の保存区分は合意内容、以下の配置・グラフ・操作の細部はレビュー用の提案です。

画面案：[admin-design-preview.html](../tests/admin-design-preview.html)。ブラウザーで直接開けます。サンプルデータだけを使い、DB・設定ファイルへ接続しません。保存ボタンは操作感の確認用です。

## 共通構成

- 上部に「Pollyanna — An Easy-to-Install Like Button System」、システム状態、Dashboard／個別詳細／設定のタブを配置する。フッター中央に正式名称と「Developed by Nikukiu-SYSTEM」を2行で表示する。
- 選択中のタブを文字・下線で示す。キーボードでも切り替えられるようにする。
- 機能タブは、ページの縁に付いたインデックスシールのような枠付きラベルで表示する。選択中は白背景で少し高くし、上辺にアクセント色を入れる。狭い画面では横スクロールできるようにする。
- 小さい画面ではカード・設定欄を縦に並べ、表は横スクロールできるようにする。
- 管理画面の基準文字サイズは16pxとし、補足文やラベルも原則14px以上で表示する。
- 管理画面の言語とサイト側の表示言語を独立させる。既存の日英JSONを本実装でも使う。
- 未保存の入力はタブ切り替え時に保持する。ページを離れるときは未保存があることを通知する。

## Dashboard

システム情報はDashboard見出しの右側に配置し、その左端を下段の「集計済み」カード内の文字位置に揃える。Dashboard見出しは34pxとする。システム情報の見出しと値は16px、項目名は14pxにし、項目間に区切り線を入れる。管理画面のLanguageもここに置き、選択時に即時反映・保存する。設定タブには重複して置かない。狭い画面では見出しの下に回し、2列の項目間に縦横の区切り線を表示する。グラフはカード群の下で横幅全体を使う。

| 表示 | 内容 |
| --- | --- |
| 総いいね数 | 集計済み累計＋未集計イベント。集計前後で総数が減ったように見せない |
| 集計済み／未集計 | 総数の内訳と集計の進行状況 |
| いいね ID数 | 集計済み・未集計の両方にあるIDを重複なしで数える。作品名やURLは推測しない |
| いいねの傾向 | 直近7日間の日別／直近1年間の月別／直近1ヶ月の時間帯別を3つのグラフとして横並びにする。各グラフの補足は対象期間とデータ説明の2行に分け、15pxで表示する。棒の間隔は3px |
| システム情報 | 実際のアプリバージョン、現在の状態、集計タイムゾーン、情報の取得時刻 |

本実装では管理画面を開いた際の既存の集計バッチを利用し、処理後に概要を再取得する。通常バッチは最大500件。画面案には実際のバージョンと紛らわしい番号を置かず「開発中（画面案）」と記載する。

最近の推移は日別集計と未集計イベントを同じタイムゾーンで足し合わせる。取得時点を揃えて二重加算を避ける。読み込み失敗を0件と表示しない。

2026-10-03の修正：日別は直近7日間、月別は当月を含む直近12ヶ月、時間帯別は当月の0〜23時を、3列で同時に表示する画面案とした。狭い画面では1列にする。当月途中であることと実際の対象期間を明記する。時間帯別は集計済みデータのみで、表に件数・割合を併記する。「直近1ヶ月」を過去30日間とする場合は、月単位の既存時間帯別データでは正確に再現できないため、期間の定義と保存方法を本実装前に決める。配色は後日調整する。

## 個別詳細

- 画面を開いたときに傾向を先に把握できるよう、時間帯別グラフを検索・一覧より上に配置する。対象月のドロップダウンは月名が収まる幅とし、対象月、選択欄、期間合計を一行に並べる。
- いいね IDで検索し、期間と日別／月別／年別の粒度を選ぶ。
- ID、対象期間、表示単位の入力欄は内容に合う幅へ縮め、左から一列に並べる。一覧の最右列には設置先URLを表示する。
- 現在のDBは設置先URLを保存していないため、本実装ではウィジェットに明示した正規URLをIDと関連付けて保存する。クエリ文字列を含む閲覧中URLを自動収集しない。同じIDを複数ページで使う場合は複数の設置先を扱えるようにする。
- 選択したIDの累計、対象期間の件数、期間別グラフと表を表示する。全IDの一覧にはページ送りを設け、最新100件への固定はやめる。
- 時間帯別はサイト全体の分析として別の枠に表示する。現在の保存構造ではIDごとの時間帯分析はできない。
- 月または年を選択し、0〜23時の棒グラフに件数と割合を表示する。割合の分母は選択期間の時間帯別件数の合計。
- 時間帯別は集計済みデータが対象であることと集計時点を示す。対象が0件なら「データがありません」と表示し、割合を計算しない。
- 時間帯別の保持期間は直近24か月。保持範囲にかかる年は「保存されている期間のみ」と表示し、欠落期間を0件扱いしない。
- 日別から月別・年別に圧縮済みの期間は細かい粒度で再現しない。利用可能な粒度と保持期間を案内する。
- グラフには対応する表を併設し、色やマウス操作だけに依存しない。

## 設定

集計タイムゾーンの選択と変更操作は「設定」見出しの右側に配置し、その左端を下段の「サイト表示設定」カードに揃える。変更時のアーカイブとリセットに関する注意文も同じ領域に表示する。狭い画面では見出しの下へ回す。

| 保存区分 | 項目 |
| --- | --- |
| 管理・運用設定を保存 | システム状態、自動集計開始しきい値 |
| サイト表示設定を保存 | サイト側の言語、成功メッセージ、1作品・1ブラウザあたり直近24時間の上限、件数表示、自動更新間隔、件数の色 |

各区分の末尾に保存ボタンを1つ置く。保存前に区分内の全項目を検証し、失敗時は入力を保持して該当項目へ案内する。一方の保存が他方の未保存入力を確定しない。保存済みと未保存の状態を表示する。画面案では保存を模擬するだけで、永続化しない。

管理画面のカラーテーマは、システム、ライト、ダーク、グリーン、ブルー、オレンジ、レッド、パープル、モノクロの9種類をプリセットで用意する。色別テーマは白基調とし、選択色をタブ・ボタン・グラフなどのポイントに使う。システムは端末のライト／ダーク設定に追従する。設定タブで選択すると即時反映し、その選択を保存する。サイト側の件数表示色とは独立させる。

件数非表示の場合、更新間隔と色は入力不可にして値を保持する。更新なしは0秒、初期値は5秒。上限は1〜5回の昇順、初期値3回。成功メッセージの選択肢は選択言語のJSONから生成する。

管理画面の言語はDashboardで選択すると即時反映・保存する。設定保存は複数の既存JSONへの個別書き込みをそのまま連続実行せず、区分単位で失敗時に一部だけ反映されない保存方法を設計する。

### 独立した操作

タイムゾーン変更は設定タブの別枠に置き、専用ボタンから対象データ・公開件数のリセットを確認する。変更後の集計、アーカイブ、完了先、中断からの再開を既存サービスへ接続する。普通の保存操作では実行しない。

必要なら残りの集計を手動で進める操作を集計状況に置く。閲覧用グラフの更新と集計実行を混同させない。
