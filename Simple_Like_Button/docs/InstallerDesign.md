# Webインストーラー設計

作成日：2026-10-03。次回作業の開始点とする。

## 目的

サーバーへファイルを配置した後、ブラウザー上の案内に従うだけでPollyannaの運用を開始できるようにする。DB設定ファイルや秘密鍵を手作業で編集しなくてよい導入経路を用意する。

## 完了条件

1. 日本語・英語を選択できる。
2. PHPバージョン、PDO MySQL、JSON、セッション、必要ディレクトリの書き込み可否を確認できる。
3. DBホスト、ポート、DB名、ユーザー名、パスワードを入力し、接続確認できる。
4. `install/install.sql` 相当の全テーブルを安全に作成できる。
5. 64桁16進数のアプリ秘密鍵を暗号学的乱数で生成する。
6. 集計タイムゾーンを選択できる。
7. 12文字以上の管理パスワードを設定できる。保存するのはハッシュだけとする。
8. `config/config.php` と `config/admin_credentials.json` を原子的に保存する。
9. 完了後に管理画面へのリンクと、ウィジェット設置例を表示する。
10. インストール済みの場合は入力画面を再表示せず、再実行を防ぐ。
11. インストール成功後は完了マーカーを保存し、`install/` ディレクトリが残っている間は管理画面へのアクセスを拒否する。これは最重要の完了条件とする。

## 画面の流れ

1. **環境確認**：必須項目を一覧表示し、失敗項目には具体的な修正先を示す。
2. **DB設定**：接続情報を入力して接続のみ確認する。パスワードは再表示しない。
3. **基本設定**：タイムゾーン、管理パスワード、確認用パスワードを入力する。パスワード表示切替を設ける。
4. **実行確認**：作成する設定・テーブルを要約する。DBパスワードや秘密鍵は表示しない。
5. **インストール**：テーブル作成、設定ファイル保存、認証情報保存を順に実行する。
6. **完了**：`install/` ディレクトリの削除を必須作業として案内する。削除前は管理画面へのリンクを有効にせず、削除後に管理画面を利用できることを説明する。READMEと埋め込み例への導線も表示する。

## 安全設計

- インストール開始から完了までセッションとCSRFトークンを使う。
- DB名・接続値をSQL文字列へ連結しない。テーブル作成SQLは同梱した固定SQLだけを使う。
- エラー画面やログへDBパスワード、秘密鍵、管理パスワードを出さない。
- 設定ファイルは一時ファイルへ書いてから置換し、途中状態を残さない。
- `config/config.php` が有効で、管理認証情報も存在する場合をインストール済みと判定する。
- インストール済み環境の修復・上書きは初版インストーラーの対象外とする。
- 正常完了時に `config/install_complete.json` を原子的に保存する。完了マーカーと `install/` ディレクトリが両方存在する間、管理画面はログイン処理より前に停止し、ディレクトリ削除だけを案内する。
- 管理画面のロック解除条件は、サーバーから `install/` ディレクトリ全体が削除されたこととする。`index.php` だけの削除や画面上の操作では解除しない。
- `log/` と `config/` のWebアクセス拒否を確認する。Apache以外では必要なサーバー設定を完了画面で案内する。
- 途中でDBテーブル作成後にファイル保存へ失敗した場合は、作成済みテーブルを消さず、再実行可能なエラーとして扱う。`CREATE TABLE IF NOT EXISTS` により再実行を安全にする。

4. 設定・秘密鍵・管理パスワードの保存を実装する。
5. 完了画面と再実行防止を実装する。

7. READMEと実装計画へ実際の操作手順・確認結果を追記する。

## 次回確認する点

- 本番サーバーで `config/` をWeb公開範囲外へ置けるか。初版では現行配置を維持し、アクセス拒否を必須確認とする。
- DBユーザーに `CREATE TABLE` 権限がない環境向けに、SQL手動実行への案内を初版へ含めるか。
- インストール完了後は `install/` ディレクトリ全体の削除を必須とし、削除までは管理画面をロックする。再実行防止には設定・認証情報と完了マーカーを使う。
